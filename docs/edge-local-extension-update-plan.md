# 开发者模式本地扩展：网站更新方案

日期：2026-09-24。约束：无管理员权限，无 IT 配合，员工已通过 Edge 开发者模式加载本地扩展目录。目标是通过自建网页完成日常版本更新。

## 结论

有条件可行，建议验证「网页获得本地目录读写授权 → 下载并校验新版 → 更新原目录 → 扩展重新加载」。这不是 CRX 自动更新服务，不能仅配置 update_url 就获得本地目录同步。无需企业策略或管理员权限的前提是目录属于当前用户且可写，浏览器允许 File System Access API，并且开发者模式保持可用。

## 两档体验

1. 不修改现有扩展：网页更新文件后，用户在 edge://extensions 点击该扩展的重新加载按钮。支持第三方或无法修改的扩展；不承诺网页自动重新加载。
2. 可修改自有扩展：加入限定商店域名的 externally_connectable 消息入口。网页写入完成后发消息，扩展验证来源与消息类型，调用 chrome.runtime.reload() 重新加载自身，网页随后重新连接并核对运行版本。这是首选目标，但必须在目标 Edge 上做 PoC。

旧扩展若没有通信入口，首次接入新版仍需手动重新加载一次。首次安装新扩展也仍需用户在扩展管理页加载解压目录。已有网页中的 content scripts 可能需要刷新相应业务页面才能运行新代码。

## 用户流程

首次：打开 HTTPS 商店 → 选择已加载扩展的原目录 → 授予读写权限 → 校验扩展身份与版本 → 更新。目录选择必须由用户完成，网页不能凭路径访问磁盘。

后续：打开商店 → 查看版本 → 点击更新 → 必要时再次授权 → 写入完成 → 自动重新加载（已接入扩展）或提示手动重新加载。目录句柄可存 IndexedDB，但不得承诺权限永久保留或跨设备同步。

## 最小架构

- HTTPS 商店：列表、最新版本、版本说明、目录绑定、更新进度、失败恢复。
- 版本服务：提供版本清单、文件清单、校验值及 ZIP 包；可复用网页登录鉴权，因为这是网页主动下载，不是 Edge 原生更新请求。
- 网页更新器：File System Access API 读取与写入用户指定目录；在浏览器解压、拒绝路径穿越、校验包与目标身份。
- 可选扩展通信：仅允许确切商店来源，提供读取自身运行版本与重新加载两个窄接口；不得接受任意代码或任意命令。

发布包中不放用户数据。更新保留原目录与扩展身份，不引导卸载重装。跨机器扩展 ID 可能不一致，实施时验证 manifest 公钥 key 固定 ID 或选择受限内容脚本桥接方案，不能假设所有员工 ID 相同。

网页文件写入不具备整个目录的原子事务：先完整下载、验证并备份原文件，再更新；最后写 manifest 并关闭全部写入句柄，之后才能触发 reload。此顺序只能降低风险，不能消除浏览器在中途重新读取文件的风险。需保留恢复记录和重试入口，只清理由旧版本清单确认的过期程序文件，不清空用户选择的目录。若实际运行证明无法可靠恢复，应退回生成新版 ZIP 和手动覆盖流程。

网站只能知道选中目录里的版本；显示“已运行新版”必须得到扩展重新加载后的版本响应，不能用文件写入成功代替安装成功。一般情况下扩展存储在同 ID 下保留，但需验证身份稳定、存储迁移和用户配置。

## PoC 验收

先用一个无业务数据的示例扩展，做 1.0.0 → 1.1.0：

1. 实际 Edge 能调用 showDirectoryPicker({mode: 'readwrite'})，在用户目录中读写 JS、JSON 等所需文件。
2. 已加载目录更新后，手动 reload 确实应用新代码。
3. 若可改扩展，网站消息触发自 reload，重连返回 1.1.0。
4. ID 与 chrome.storage 数据保持，必要业务页面刷新后功能正常。
5. 用户取消授权、目录选错、下载失败、写入中断时不虚报成功，备份能恢复。
6. 关闭重开浏览器后目录句柄与授权行为可解释，权限失效时有重新授权入口。

当前仅完成官方文档研究，没有目标 Edge 实机测试，不能称为已验证的一键更新产品。是否拥有扩展源码和修改权仍待确认。

## 官方依据

- [File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)：用户选择目录和授权后访问文件、写入、句柄持久化。Chromium 文档作为能力依据，目标 Edge 与公司策略需实测。
- [Runtime API](https://developer.chrome.com/docs/extensions/reference/api/runtime)：reload 重新加载自身；unpacked reload 触发 update 类型的 onInstalled。
- [网页与扩展通信](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)：通过 externally_connectable 限定可通信网站。
- [扩展开发入门](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world)：本地加载及修改后的重新加载流程。

本方案不修改企业策略，不提供规避已生效策略的机制。若浏览器或设备禁用所需能力，使用人工更新或申请正式分发渠道。
