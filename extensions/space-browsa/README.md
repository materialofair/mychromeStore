# SPACE AI（基于 browsa）

这是 [browsa](https://github.com/xiaohuzai/browsa) 的可复现适配配方。固定源码提交见 `upstream.json`；保留侧栏聊天、网页/选区上下文、PDF、视频和原有模型配置入口。没有使用 Sider 的代码。商店与适配代码使用 MIT，browsa 的 MIT 声明及第三方组件许可随安装包分发。

## 构建

在仓库根目录使用 Node 22.13+、npm、Git、tar：

```sh
npm ci
npm run browsa:build
```

输出 `.data/packages/space-browsa-1.0.1/`（可加载目录）及同名 ZIP。首次构建下载固定源码和锁定依赖，运行依赖审计、重建 npm 支持的 vendor，并运行模型相关 72 项上游测试。构建保留其它上游预编译 vendor；其身份与许可见 `notices/`。`npm audit` 不覆盖这些预编译文件，不代表全部上游代码已完成安全审计。

线上部署必须将构建来源设为实际商店的精确 HTTPS origin（不带路径或末尾斜杠）：

```sh
STORE_ORIGIN=https://extensions.example.com npm run browsa:build
```

默认仅允许 `http://localhost:5173`。桥接只支持身份/版本查询和重新加载，不暴露 API Key、聊天或页面数据。`identity.json` 是固定公钥，不是秘密，也不能作为上传者身份凭据。不要在版本间更换它；上传和审核由平台账户权限控制。

后续适配版本：`SPACE_BROWSA_VERSION=1.0.2 npm run browsa:build`。已有输出不会被覆盖，避免误改浏览器正在加载的文件夹。如需重建同版，先把旧产物移到其它位置；商店中使用过的版本号不能重新上传。

## 发布和安装

1. 管理员用 `npm run admin:create` 建立首个账户，并在发布中心创建开发者和审核者。
2. 开发者上传生成的 ZIP；另一名审核者检查文件和权限后批准，才会出现在公开目录。管理员也不能批准自己的上传。
3. 用户下载、解压到固定目录，在 `edge://extensions` 打开开发者模式并「加载解压缩的扩展」。首次安装仍需这一步。
4. 在商店发布中心点击该扩展的「安装与更新」，绑定刚才实际加载的目录。后续批准的更高版本可由网页备份、写入和通知重载。

浏览器不允许网站静默首次安装。目录授权可能需要再次确认；重载验证失败时页面会提示手动操作。更新前结束进行中的聊天。旧版已下架时，网页会停止更新，需手动下载新版；不会绕过审核读取下架包。本地身份正确的备份仍可恢复。

## 自定义模型

打开扩展设置，在 LLM 卡片填写 Base URL（通常到 `/v1`）、API Key，添加模型 ID，API 选择 Chat Completions，保存并激活该卡片。支持同一服务的多个模型，保留 browsa 原有 Responses/Anthropic 和 Agent 配置入口。

Key 保存在该扩展的 `chrome.storage.local`，并发送给用户配置的模型服务；这不是加密保险库。商店上传包和更新桥接不会读取这些设置。新 ID 与官方 browsa 独立，官方版本的现有配置不会自动迁移。固定 ID 的版本更新会保留扩展存储。

本扩展保留上游广泛页面访问、cookies、下载等权限；审批页会列出权限。网站提取、ASR、远程 Agent 等能力依赖对应站点与服务，不能仅凭通用聊天测试认为所有外部服务均已验证。

## 修改源码

`scripts/build-browsa.mjs` 从固定 Git commit 导出干净源码，再应用本目录的锁文件、身份和桥接。缓存工作树的手工改动不会进入产物。修改适配请更改这里的配方；需要修改上游业务代码时，应在仓库中增加可追踪补丁并由构建脚本应用，或将 `upstream.json` 指向你维护的公开 fork 和固定 commit。

完整上游源码及测试可从 `upstream.json` 的仓库/提交获取；构建产物、用户数据库、模型密钥不提交到 Git。

## 1.0.1 阅读体验

- 「总结」先读取当前网页再发送；已有草稿、图片或文档附件时保留内容并提示先处理，不覆盖输入。
- 网页正文与文档资料默认折叠为来源和文件名，点击「查看本次资料」可展开；重新打开历史也保持折叠，复制和重试仍使用完整原始内容。
- 划词浮层支持键盘选区，输入区域不弹出；窄窗口内限制浮层尺寸，Escape 关闭。
- 文件入口和拖放支持 TXT、Markdown、PDF；文档显示解析状态和删除按钮，只有点击发送才把已解析内容交给模型。
- 最多 5 个文档，每个 10 MiB，总提取文本 100,000 字符，PDF 最多 100 页。超限或无文字明确提示；扫描 PDF 不做 OCR。图片沿用原有处理。
- 切换会话或页面会清除尚未发送的文档，避免发送到错误上下文；移除后即使解析完成也不会重新附加。

阅读与附件修改由 `reading-patch.mjs` 和 `attachments-patch.mjs` 应用，源码位于 `reading/` 和 `attachments/`。补丁锚点失配时构建停止；安装包的 `SPACE-PROVENANCE.json` 记录配方文件哈希。
